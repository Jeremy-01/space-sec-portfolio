# 阶段 C：安全分析

> 📍 [作品集首页](../README.md) › **阶段 C：安全分析**

**目标**：把阶段 A（协议能力）+ 阶段 B（真实信号）缝成一份有观点的安全分析报告，证明"能独立做安全研究"。

## 分析对象（选一类真实空间链路）
候选：某业余卫星遥测下行 / NOAA 广播 / 某公开协议实现。

## 分析维度（仅被动观测 + 仿真）
- **机密性**：下行是否加密？
- **完整性/认证**：帧是否有认证？可否被动重放？
- **GNSS 欺骗**：可行性边界（理论 + 仿真，不实施）
- **协议弱点**：对照 CCSDS 规范找设计层面的安全缺口

## AI 运用（见 [ai-workflow.md](../docs/ai-workflow.md)）
- **副驾**：AI 辅助大批量遥测的模式挖掘、辅助起草报告。
- **AI-as-subject（本阶段核心贡献）**：构建 **AI 辅助威胁建模 / 遥测异常检测**流程，作为报告的方法亮点，把 A+B 的 AI 能力收口成一条"AI×空间安全"主线。
- 所有 AI 生成的安全结论必须人工核实后才纳入报告，并标注验证状态。

## 方法论要求
- 结论必须有据：抓包/解码证据、协议规范引用、仿真结果
- **明确区分"已验证"与"推断"**（AI 生成的结论同样适用）
- 不实施主动攻击验证漏洞（见 [ethics-and-legal.md](../docs/ethics-and-legal.md)）
- 若发现真实系统疑似漏洞 → 走负责任披露

## 产出
- 结构化安全分析报告 / 白皮书
- 复现仓库（数据 + 分析脚本）
